# SSH tools (done 2026-09-24)

The user asked for a remote/SSH plugin "so the agents do not need to pass scripts and large blocks of code through
flaky pwsh/bash arguments", using the passwordless keys in `~/.ssh`. Kept for reference; the tools are described in
`docs/TOOLS.md` (SSH tools), their settings in `docs/SETTINGS.md`.

## Decisions (the plan's open questions)

- **Hosts:** read the aliases from `~/.ssh/config` on every call, nothing hard-coded, and allow all of them. There is no
  `ssh.hosts` filter.
- **Tool set:** phase 1 as planned. No background jobs.
- **Host keys:** unknown host keys are rejected (`StrictHostKeyChecking=yes`); the user connects to a new host once
  first. There is no `acceptNewHostKeys` setting.
- **Live tests** on `nuc` and `server`, under `/tmp`, cleaned up.

## What was built (`plugins/NetPI.Tools.Ssh`)

| tool | how |
|---|---|
| `ssh_hosts` | the concrete `Host` aliases (`Include` followed, wildcards/negations/`Match` skipped) with user, HostName, port |
| `ssh_run` | stdin carries `cd <cwd>` and the script; the fixed remote line saves it to a `mktemp` file and runs `setsid --wait bash -c 'echo pgid; exec timeout -k 5 T bash file'`. A timeout ends the group through `timeout`; an abort sends TERM then KILL to the group over a second connection |
| `ssh_read` | `stat` + `head -c 8MB` in one call; paging like `read` |
| `ssh_write` | `cat >file` (or `>>`) with the content on stdin; `mkdir -p` for the parent |
| `ssh_edit` | read, apply the edits locally (`TextEdits`, same rules as `edit`), write back only if size and mtime are unchanged |
| `ssh_copy` | `scp -p [-r]`, run in the local folder with `./name` so a drive letter is never read as a host |

All calls share `BatchMode=yes`, `StrictHostKeyChecking=yes`, `ConnectTimeout`, keep-alives and `LogLevel=ERROR`, and
pass `-F` when `ssh.config` points elsewhere. The UI reuses the shell, read and diff views (`web/src/lib/tools.js`).

Changes from the plan:
- `ssh_write` writes in place instead of to a temp file plus rename, so the file keeps its owner and permissions.
- `ssh_hosts` does not probe the OS or shells.
- The unit tests replace the launcher (`ISshLauncher`) instead of a fake `ssh` executable.
- `ssh_run` output follows `bash`: the last 2000 lines / 30KB, with the whole output saved to a temp log when cut.
- The launcher keeps more stdout than `ssh_read` fetches; with the first 4 MB cap, files of 4–8 MB failed to read.

## Tests

- Aux suite: 10 SSH tests with the fake launcher (arguments, byte-exact stdin, exit codes, timeout/abort, truncation
  and the saved log, config parsing, edits and diffs, scp arguments) plus `ssh live`, which runs only with
  `NETPI_SSH_TEST_HOSTS`.
- Live on `nuc` and `server` (about 33 s):
  - a script full of quoting traps came back byte for byte;
  - write, read and edit, with a space in the path and relative to `cwd`, including a 5 MB file;
  - a 70 KB binary copied up and back unchanged;
  - a timeout and an abort each ended `sleep` children started in the background;
  - afterwards neither host had test folders or leftover processes.
