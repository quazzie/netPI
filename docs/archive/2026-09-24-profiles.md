# Profiles, and subagent tools chosen by their owner (done 2026-09-24)

The user asked for profiles that change the system prompt and the tools, a default profile per project, and switching
a chat's profile at the price of a re-read (free before the first message). Kept for reference: the settings are in
`docs/SETTINGS.md` (Profiles), the RPCs in `docs/PROTOCOL.md`, the tool rules in `docs/TOOLS.md` ("Which tools an
agent is sent"), the UI in `docs/UI.md`.

## Decisions with the user (2026-09-24)

- **A profile is instructions and tools.** No model or reasoning effort. The instructions replace the opening of the
  system prompt ("You are a system administrator …"). The tools are switched with checkboxes, never typed by name.
- **Switching in a started chat renders the system prompt again.** A notice alone would be cheaper, but the tools lead
  every request and change anyway, so the chat is read again in full either way.
- **Subagents don't use profiles; their owner chooses their tools.** For example, a limited admin that dispatches an
  agent with the SSH tools it does not have itself. By default a subagent gets its owner's tools. With an
  `agent_spawn` `tools` list it gets exactly those, including tools its owner lacks.

## As built

- **`plugins/NetPI.Profiles`:**
  - settings `profiles.<id> = { name, prompt, toolsOff }` and `profiles.defaultProfile`;
  - `profiles.list`, `profiles.apply { sessionId, profile }`.
  - Applying a profile sets the chat's `meta.profile`, `meta.identity` (the prompt text) and `meta.toolsOff` (its tool
    switches, which the tools button can still change).
  - A new chat gets its project's default (`project.meta.profile`, or `"none"`), else the global one: on
    `session.created` for the UI, and at the latest in a run-start hook, so a quick first message cannot miss it. An
    older chat is never changed by a new default.
  - In a started chat a switch calls `context.reset` and appends a `profile` notice.
- **Host:** `ProjectInfo.Meta` (additive; a migration adds the column), and `projects.update { meta }` merged key by
  key.
- **Context plugin:**
  - the identity section uses the chat's `meta.identity` first (`SessionIdentity`, additive);
  - `context.reset` forgets a chat's frozen prompt and tool baseline;
  - a tool baseline records the last message seq when it was taken, so "tools" notices from before a switch no longer
    count.
- **Agent plugin:** the runner reads the chat again after the run-start hooks; a subagent's tools follow the owner's
  choice; `agent_spawn` answers an unknown tool name with the list of tools by category.
- **UI:**
  - the Profiles settings page ("New chats start with", one card per profile with the instructions and tool checkboxes
    by category);
  - a profile picker next to the model (free before the first message; the re-read warning after it);
  - "Profile of new sessions" in the Projects dialog;
  - the `profile` notice.

## Results

Agent suite 82 (3 profile tests: new chats, switching, boundaries; the subagent tool rule), Host 38 (project meta), E2E
55 / 703 checks, UI mock e2e 160 (the Profiles page, a project default, a new chat with it, switching before and after
the first message).
